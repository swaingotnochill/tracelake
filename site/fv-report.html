Formal Verification Implementation Report

Outcome of the phased plan in formal-verification-brief.md, stages 0-4.

Landed

  • Stage 0 — rocq-of-rust assessment committed (2d40fdd): PASS.
  • Stage 1 — property suite committed (c7cc852): key codec (round-trip, ordering, prefix isolation/nesting, totality), bloom (no false negatives, membership-exact round-trip, totality, FPR bound), trace pack (exact round-trip, prefix rejection, totality), segment manifest (JSON round-trip, next-segment law, exhaustive id formatting), merge laws L1-L5, group_spans partition law, search helper laws (prune soundness, per-filter exactness, completeness). 88 workspace tests green.
  • Bug found and fixed by the suite: serde_json's default best-effort float parsing shifted cost_usd-like values by one ULP across pack round-trips (172.0*0.001 -> 0.172). Fixed with the serde_json float_roundtrip feature; regression test in trace_pack.rs. This was silent data corruption in the flagship read path.
  • Stage 2 — Kani harnesses: key.rs (3), bloom.rs (3), trace_pack.rs (2, including the checksum-restamped corruption totality), merge.rs (L3 last-layer-wins, L4 no-loss). search helpers stay PROPERTY tier: chrono DateTime has no symbolic construction under Kani (documented in docs/verification.md debts).
  • Stage 3 — docs/verification.md (tiers, trusted boundaries, coverage manifest, agent protocol) + AGENTS.md verification protocol section.
  • Stage 4 — CI: check (fmt/clippy/tests), kani job (paths-filtered to core/query), nightly Miri on core (non-blocking).

Kani run status — honest note

Local cargo kani on this Apple Silicon machine compiles quickly but each CBMC solve takes minutes (the pack harnesses pull serde_json's serializer under the solver; unwinds up to 128). Interactive completion of the full harness set was not practical in one session; three bounded local runs reached the solving phase without finishing. The CI kani job is the authoritative gate. Expect possible per-harness unwind tuning on the first CI run; that is normal Kani adoption work and is covered by the protocol in docs/verification.md (never delete a property to make it pass).

Session 2: making the proofs actually run (completing stage 2)

Kani harnesses were written but no proof had completed. Findings and fixes:

  1. CI workflow invalid (job-level paths: key, 0-second failure). Split into ci.yml (check + miri) and kani.yml (own on.push.paths filter).
  2. merge harness did not compile (move-after-borrow) — cfg(kani) code never builds under normal cargo; only a Kani run catches it.
  3. Solver walls found and removed by restructuring (each documented in docs/verification.md):
  4. format!/std parse in the key path -> extracted pure encode_timestamp_bytes + parse_timestamp_digits; proofs target the codec core. PROVEN locally: digit-fold totality.
  5. macOS OS RNG inside HashMap::new() (RandomState -> CCRandomGenerateBytes, a foreign C call Kani cannot run) blocked merge proofs -> merge_spans now uses BuildHasherDefault&lt;DefaultHasher&gt; (deterministic, identical semantics, reproducible merges).
  6. SipHash over symbolic keys exploded the SAT instance in bloom -> extracted bit_position (shared by insert/contains, making no-false-negative structural) and proved it in-bounds; hashing stays out of the solver.
  7. serde_json in pack harnesses -> hand-built minimal pack bytes; the corruption-totality proof covers checksum/header/directory without parsing span JSON.
  8. Locally VERIFIED (this machine): bloom bit-position bounds, bloom decode totality, key digit-fold totality. Full-key round-trip/ordering, merge L3/L4, and pack corruption solve slowly on Apple Silicon (20+ minutes each; bit-blasted 64-bit division chains and hashbrown insert paths) — they are queued for the CI x86_64 runner, which is the authoritative gate per docs/verification.md.
  9. All proptests stay green through every production change (88+ tests); the byte-assembly refactor of encode_span_key is pinned by the round-trip properties.
