Gap analysis: TraceLake against SmithDB and Brainstore

Written at the alpha milestone on 2026-10-31. Sources are the vendor architecture posts listed at the end.

What each system is

SmithDB is LangChain's data layer for LangSmith. It is an object-storage-backed LSM with a Vortex columnar format, Apache DataFusion for analytics, a small Postgres metastore for segment metadata, and stateless ingestion, query, and compaction services. It reports sub-100 ms trace loads and sub-second full-text search.

Brainstore is Braintrust's engine. Every write appends to a write-ahead log on object storage, and continuous compaction turns segments into a row store, a Tantivy inverted index, a column store, vector indexes, and bloom filters. It reports under 50 ms hot and under 500 ms cold full-text search, and it treats semi-structured fields as first class instead of shredding JSON into a fixed schema.

Trace fetch is range-based as of the performance review: a lookup reads the header, the directory, and one trace block, so its cost follows trace size rather than segment size. See performance.md.

Gaps that matter for alpha

  1. Compaction is single-threaded and has no scheduler. It now compacts only keys above a per-namespace watermark and deletes those hot keys, so repeat runs do no work and segments hold each record once. The first compaction still builds one segment from the whole hot buffer. Late keys below the watermark stay in the hot store.
  2. Deletes are reclaimed on compaction. Tombstones mask deleted rows, and compaction rewrites affected segments without them. Retention deletes by cutoff. Tombstone entries themselves stay in the manifest.
  3. Analytics are incomplete. Aggregation over Parquet columns is landing in this milestone. SmithDB and Brainstore already serve percentiles and grouped counts.
  4. One server, one process. The architecture is stateless by construction, but the server still owns an in-process hot store. Running two servers against one object store is untested.
  5. No OTLP or SDK. Every client must speak the JSON API. This blocks the common adoption path.
  6. Text search over hot data caches one index per namespace. It rebuilds after a hot write. SmithDB and Brainstore index at L0 and in the WAL, so their first search after a write does not pay a full rebuild.

Gaps that can wait

  • Vector search. Out of scope per AGENTS.md, and not needed for trace debugging.
  • A Postgres metastore. JSON manifests are enough while one compactor owns a namespace. SmithDB's metastore buys transactional handoff between stateless services.
  • Multi-region replication. Object storage already handles durability.
  • Compression tuning. Packs store JSON. Zstd over pack blocks and Parquet encoding will close most of the size gap.
  • Payload preview so list queries do not deserialize multi-megabyte fields.

What to do next, in order

  1. Compaction watermark and hot-key drop, so segments stop duplicating records.
  2. Deletes and retention with tombstones that survive compaction.
  3. Aggregation coverage for span percentiles by model and status.
  4. OTLP ingestion and a small client SDK.
  5. Query timeouts and per-tenant limits, then authentication.
