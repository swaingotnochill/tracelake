Alpha readiness

This is the alpha checklist for TraceLake as a trace database. It states what a user can do today, what is required before calling the release an alpha, and what is explicitly out of scope.

Required before the alpha tag

  1. A live S3 or GCS run in CI or a staging environment. The store selection is tested and the code paths compile, but no bucket credentials are available here.

Operational notes

  • Read limits are set by TRACELAKE_QUERY_TIMEOUT_MS (default 30000) and TRACELAKE_TENANT_CONCURRENCY (default 16). The cap is per process and per tenant name. A request over the cap gets 429. A request past the timeout gets
  • The timeout wraps the database call; the permit is released when the call returns, times out, or is cancelled.
  • TRACELAKE_STORE selects local (default), s3, or gcs. TRACELAKE_BUCKET names the bucket. TRACELAKE_REGION and TRACELAKE_ENDPOINT configure S3 or an S3-compatible server such as MinIO. TRACELAKE_PREFIX scopes remote paths and defaults to tracelake. Credentials come from the provider chain (AWS_* or GOOGLE_*); the server never reads keys from its own settings.
  • For a local store, the server writes the hot store and segments under TRACELAKE_DATA_DIR. Back up that directory, or the bucket prefix on object storage.
  • One server process owns a data directory. Two processes against one directory are untested.
  • Compaction is triggered by POST /v1/compact; there is no background scheduler yet. It compacts keys above each namespace watermark, publishes the segment, then deletes those hot keys. A crash between publish and delete leaves duplicates that the watermark skips on the next run.
  • A span or record that arrives with a key below the watermark stays in the hot store and is served from there. It is not copied into a segment. This keeps late data readable while hot data is retained, and is a limitation once hot retention exists.
  • Deletes write a tombstone under v1/d/, remove the hot copy, and mask compacted copies. Compaction folds tombstones into the manifest, rewrites any segment whose bloom names a tombstoned id, drops the deleted rows, removes a segment that becomes empty, and deletes the old files. Retention deletes traces whose latest span starts before the cutoff.
  • Bind to loopback or a private network. There is no authentication.

Out of scope for alpha

  • Vector search and embedding indexes.
  • Multi-region replication.
  • A SQL surface. Queries are typed structs and JSON.
  • Authentication, RBAC, and audit logs.
