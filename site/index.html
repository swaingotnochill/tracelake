TraceLake

A trace database for LLM agents. Object storage is the source of truth, SlateDB is the hot write buffer, and compaction writes trace packs, typed record packs, Parquet columns, bloom filters, and Tantivy indexes. Full traces, typed tables, eval logs, search, and aggregation come from one engine.

Start here

HTTP APIEvery endpoint, shape, limit, and status code. Custom tablesTyped schemas, evolution rules, records, and queries. ArchitectureStorage layout, write and read paths, and the decisions behind them. inspect-ai evalsA real eval run through ingest and query.

Run it

cargo run --release -p tracelake-server
cargo test --workspace
cargo run --release -p tracelake-bench
cargo run -p tracelake-server --example inspect_ai_demo

The server writes to ./tracelake-data by default. Set TRACELAKE_STORE to s3 or gcs for object storage. There is no authentication; bind to loopback or a private network.

Where the project stands

Ingest, trace fetch, structural and full-text search, Parquet aggregation, typed tables with evolution, inspect-ai eval ingest, deletes, retention, read limits, and local or remote object storage are implemented. Open work is listed in Alpha readiness. Gaps against SmithDB and Brainstore are in Gap analysis.
